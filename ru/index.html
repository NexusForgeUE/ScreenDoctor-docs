ScreenDoctor 1.0.0 проверяет UI в Unreal Engine 5.5-5.8 на Windows 64-bit. Он работает с UMG, системой Unreal для создания меню, кнопок и других игровых экранов.

Впервые открыли Unreal? Начните с небольшого примера ниже. Fixture - Blueprint-адаптер, который открывает экран для теста. Scenario - последовательность проверок. Suite - набор сценариев и условий их запуска.

Плагин выполняет описанные вами пути. Он не исследует все меню самостоятельно и не исправляет UI автоматически. Объяснения переведены, а английские подписи кнопок и названия Blueprint-узлов сохранены, чтобы их можно было найти в интерфейсе.

Установка и открытие плагина

Выберите версию движка

Используйте пакет ScreenDoctor для вашей версии Unreal Engine: 5.5, 5.6, 5.7 или 5.8. В Epic Games Launcher номер указан под установленным движком в Unreal Engine > Library.

Установка через Fab

  1. Закройте Unreal Editor. В Epic Games Launcher откройте библиотеку Fab, найдите ScreenDoctor и установите его для движка, которым открывается ваш проект.
  2. Откройте проект. В меню Edit > Plugins найдите ScreenDoctor и включите его, если он еще выключен. Перезапустите редактор, когда он предложит это сделать.
  3. Выберите Tools > ScreenDoctor. Откроется вкладка плагина.

Установка из ZIP в проект

Папка проекта - та, где лежит файл .uproject. Если папки Plugins нет, создайте ее. Закройте Unreal и распакуйте плагин со следующей вложенностью:

MyGame/
  MyGame.uproject
  Content/
  Plugins/
    ScreenDoctor/
      ScreenDoctor.uplugin
      Resources/
      Source/

После распаковки откройте проект, включите ScreenDoctor через Edit > Plugins, перезапустите редактор и откройте Tools > ScreenDoctor. В готовом скомпилированном пакете также есть Binaries. Устанавливайте одну копию: в движок или в проект. Пакет только с исходниками требует совместимых C++-компонентов Visual Studio и Windows SDK, даже если игра написана на Blueprint. Если не хотите собирать исходники, используйте готовый пакет для своей версии движка.

Если проекта еще нет

Запустите Unreal, выберите Games > Blank > Blueprint, задайте имя и нажмите Create. Сохраните проект в понятную папку. Откройте Content Drawer внизу редактора или нажмите Ctrl+Space. Здесь хранятся ассеты: сохраненные объекты проекта, например виджеты и сценарии проверок.

Первая проверка с пустого проекта

Начните с одного экрана, языка и разрешения. C++ для создания этого примера не нужен. В руководстве используются английские названия меню и узлов Unreal; в другом языке редактора выбирайте соответствующие пункты.

  1. В Content Drawer откройте Content. Щелкните по пустому месту правой кнопкой, выберите New Folder и назовите папку UITests.
  2. Внутри папки выберите правой кнопкой User Interface > Widget Blueprint. Если появится выбор родителя, укажите User Widget. Назовите ассет WBP_UIExample и откройте двойным щелчком.
  3. В режиме Designer добавьте из Palette Canvas Panel, если корневой панели еще нет. Внутрь поместите Text. В Hierarchy назовите его TitleLabel и включите Is Variable в Details. Задайте текст ровно Settings, размер шрифта 32, позицию Canvas X=100, Y=100 и размер 600 x 100.
  4. Добавьте в Canvas Button, назовите ContinueButton, включите Is Variable и Is Focusable. Задайте позицию X=100, Y=250 и размер 300 x 70. Внутрь кнопки поместите Text с подписью Continue. Заголовок и кнопка должны быть соседями в Canvas, а не находиться друг в друге.
  5. Нажмите Compile и Save в редакторе виджета. При необходимости закройте вкладку ассета.
  6. Выполните разделы Подключение виджета и Создание сценария, затем вернитесь к следующему шагу.
  7. На вкладке Suites нажмите Create suite и сохраните DA_UIFirstSuite в Content/UITests. Нажмите Edit suite properties и задайте SuiteId = first_ui_suite. В компактном окне после редактирования нажмите Back to controls. В Scenarios выберите DA_UIFirstScenario и нажмите Add scenario to suite.
  8. В Matrix добавьте 1280 x 720 через Add resolution, затем удалите начальный 1280 x 800 кнопкой Remove, если он есть. Оставьте только это разрешение, масштаб текста 100%, культуру en и ввод Keyboard. Языки и ввод меняются через Edit cultures, input modes, exclusions and case limit. В компактном окне вернитесь через Back to controls. Запуск готового packaged-приложения пока не включайте.
  9. Нажмите Preview selected cases and exclusions, выберите единственный случай и нажмите Save and run selected case. Виджет откроется в отдельном процессе проверки. Обычную кнопку Play редактора нажимать не требуется.
  10. Откройте Runs, выберите завершенный результат и его изображение. Проверьте пять описанных шагов и снимок menu_state. Первый сценарий сохраняет изображение без сравнения с эталоном; совпадение с эталоном он еще не доказывает.
Сохраните сам UI. Перед запуском компилируйте и сохраняйте виджет и fixture. Кнопка Run сохраняет suite и scenario, но не компилирует и не сохраняет все Blueprint вашей игры.

Подключение виджета через fixture

Fixture - Blueprint с родителем ScreenDoctorFixture. Он создает экран, регистрирует нужные контролы и сообщает о готовности UI. Fixture не нужно размещать на уровне или добавлять в viewport как виджет.

Создайте ассет

  1. Откройте Tools > ScreenDoctor > Scenarios. Нажмите Create scenario, сохраните DA_UIFirstScenario в Content/UITests и оставьте выбранным.
  2. Нажмите Create Blueprint fixture, сохраните BP_UIFixture в ту же папку и откройте его через Content Drawer. Кнопка назначает fixture сценарию, но создает пустой Blueprint, а не готовое меню.
  3. В панели My Blueprint добавьте переменную Menu типа WBP_UIExample Object Reference и нажмите Compile. В меню Overrides раздела Functions выберите OpenScreen.

OpenScreen: создайте и верните UI

Узлы добавляются правой кнопкой в графе функции. Соединяйте белые исполнительные контакты по порядку. В Create Widget выберите класс WBP_UIExample, а в Owning Player подключите Get Player из fixture. Запишите Return Value в Menu и унаследованную переменную RootWidget. Если RootWidget не видна, включите Show Inherited Variables.

OpenScreen
  Create Widget (Class = WBP_UIExample, Owning Player = GetPlayer)
  -> Set Menu = Return Value
  -> Set RootWidget = Menu
  -> Add to Viewport (Target = Menu)
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = title, Context = ""
       Widget: Menu.TitleLabel
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = continue, Context = ""
       Widget: Menu.ContinueButton
  -> Return Menu

У каждого узла Register Widget подключите Target к Get Registry. В контакт Locator подключите Make Screen Doctor Locator или разделите struct-контакт и введите три поля отдельно. Из Menu получите настоящий объект TitleLabel или ContinueButton и подключите к Widget. В конце верните Menu через результат функции. Здесь возвращается объект виджета, не boolean.

IsReady: дождитесь экрана

Добавьте override IsReady. Проверьте Menu узлом Is Valid через Branch. Если объекта нет, верните false. Если есть, верните результат Is In Viewport для Menu. Пустая родительская реализация всегда возвращает false и приводит к таймауту готовности.

CleanupCase: уберите состояние теста

Добавьте CleanupCase. На входном узле функции выберите правой кнопкой Add Call to Parent Function, соедините вызов, затем очистите Menu в None. Родитель удалит RootWidget и сбросит реестр. В этом примере с отдельным процессом оставьте CaptureInputState и RestoreInputState с исходными реализациями. Нажмите Compile и Save и перейдите к сценарию.

Первый fixture работает с обычными 100%. Другие размеры текста добавляйте после подключения реального масштабирования из раздела Matrix.

Опишите действия и проверки сценария

В Scenarios выберите DA_UIFirstScenario. Задайте ScenarioId = first_ui, Revision = 1 и убедитесь, что Fixture Class указывает на BP_UIFixture.

  1. Нажмите Edit fixture / steps. В Details раскройте массив Steps и кнопкой + добавьте пять элементов.
  2. Раскройте каждый элемент и внесите значения из таблицы в указанном порядке. Оставьте Required включенным. Для первых четырех шагов задайте таймаут 5 секунд.
  3. У шагов с целью раскройте Target, введите ScreenId и TestId в разные поля, Context оставьте пустым. У AnalyzeLayout добавьте один элемент в Layout > Targets с такими же полями локатора.

Текст Settings должен точно совпадать с Text в виджете. Compare Baseline = false означает снятую галочку на шаге снимка. Позже ее можно включить для сравнения с эталоном.

Выбор шага в списке слева открывает его редактор. StepId должен быть уникальным. После переименования, удаления или дублирования снова выберите нужный шаг. Сохраняйте ID для одной и той же задачи; при намеренном изменении условий сценария увеличивайте Revision.

Если компактное окно показывает Details, нажмите Back to controls. Вернитесь к первой проверке, создайте suite и запустите один случай, прежде чем расширять матрицу.

Стабильные идентификаторы виджетов

Локатор - постоянный адрес виджета из трех отдельных полей:

ПолеПримерНазначение
ScreenIddemo_menuЭкран, которому принадлежит контрол.
TestIdtitleКонтрол внутри экрана.
Contextпусто или item:42Необязательный ключ повторяющегося элемента списка.

Регистрируйте эти поля вместе с настоящей ссылкой на виджет при открытии экрана. Не вставляйте всю строку demo_menu/title в TestId. Переведенная подпись, координаты и порядковый номер дочернего элемента не подходят для стабильного ID.

В первом примере вводите ID вручную. Refresh IDs и Assign locator to selected StepId читают реестр активного fixture ScreenDoctor в PIE. Обычный Play не создает этот fixture и не сканирует все виджеты игры.

Если у двух разных живых виджетов один локатор, результат неоднозначен. Задайте разные ID или Context. Для виртуализированного инвентаря адаптер должен сначала прокрутить список и создать виджет нужного предмета. Еще не созданный элемент сам по себе не является ошибкой UI.

Разрешения, языки и размер текста

Выберите suite и откройте Matrix. Ограничения на три разрешения нет: можно добавлять 4K, широкие, портретные и другие размеры viewport.

  1. В Viewport resolutions введите целые Width и Height, нажмите Add resolution. Каждая сторона может быть от 1 до 16384. Кнопка Remove удаляет соответствующую строку. Должен остаться хотя бы один корректный размер.
  2. В Text scales введите процент, например 125, и нажмите Add text scale. Ненужные значения удаляются рядом со строкой. Поле процентов принимает 125, а свойство TextScales хранит 1.25.
  3. Через Edit cultures, input modes, exclusions and case limit добавьте культуры, например en, de, fr, и нужные режимы ввода. В игре уже должны быть переводы и шрифты для этих языков. Выбор культуры не переводит текст самостоятельно.
  4. Заново посмотрите план. Каждый сценарий комбинируется со всеми разрешениями, языками, масштабами и вводом, затем применяются исключения. Для одного сценария и ввода два разрешения, три языка и два масштаба дадут 12 случаев.
  5. Сначала выполните выбранный случай, затем Save and run suite. При выборе более 20 случаев нужно подтвердить оценку. Case Limit ограничивает план, а Exclusions исключают указанные сочетания.

Как применить масштаб к настоящему UI

Для этого fixture реализует ApplyTextScale. По умолчанию поддерживается только 1.0. В BP_UIFixture создайте float-переменную RequestedScale с начальным значением 1.0. В override ApplyTextScale проверьте Scale > 0 и Scale <= 3: при выполнении условия сохраните Scale в RequestedScale и верните true, иначе false. Это диапазон учебного адаптера. Вызов происходит до OpenScreen, когда Menu еще не создан.

В OpenScreen, после Set Menu и перед Add to Viewport, получите Menu.TitleLabel, затем Get Font. Подключите результат к Break Slate Font Info и добавьте Make Slate Font Info. Перенесите одноимённые поля из Break в Make: Font Family (Font Object), Typeface (Typeface Font Name), материал, обводку и остальные доступные параметры. Только для Size используйте Round(32 * RequestedScale) вместо прежнего размера. Результат Make передайте в Set Font у Menu.TitleLabel, подключив белые исполнительные пины. Если узлы не находятся, тяните от пина шрифта и ищите Slate Font Info. Этот минимальный пример увеличивает заголовок; примените такую же политику к остальным текстам или вызовите реальную настройку игры. Всегда считайте от сохранённого базового размера, а не от уже увеличенного.

Viewport - область рисования. Масштаб текста - настройка вашей игры. Масштаб Windows и физический DPI монитора являются другими параметрами: ввод 125% в Matrix не меняет DPI Windows.

Как читать результаты в Runs

  1. Откройте Runs и выберите завершенный запуск в верхнем списке.
  2. Слева выберите сценарий, затем checkpoint и режим ввода. Колонки соответствуют разрешениям и масштабу текста, строки - языкам.
  3. Используйте All cases, Needs review, Passed и More filters. Исключенные сочетания могут входить в общие счетчики атласа, но выполненными тестами они не являются.
  4. Выберите ячейку и нажмите Inspect case. Через Next finding просматривайте проверки, локатор, Expected и Actual.
  5. Кнопка 100% показывает пиксели в натуральном размере; изображение можно прокручивать. Fit возвращает вписывание. Open original открывает файл изображения. Geometry snapshot - отдельный замер, а не наложение, точно соответствующее каждому пикселю снимка.
СтатусЗначениеСледующее действие
PassedОбязательные проверки случая прошли.Посмотрите и необязательные замечания.
Needs review / ReviewNeededЕсть условие для визуальной оценки, например текст за границей области отсечения.Изучите указанный виджет и снимок.
NoBaselineНет совместимого одобренного эталона.Проверьте и явно одобрите правильный снимок.
FailedОжидаемое условие сценария не выполнено.Прочитайте Expected, Actual и проблемный шаг.
Error / ErroredОшибка настройки, выполнения, хранения или инфраструктуры.Посмотрите причину и журнал процесса.
UnsupportedЗапрошенная возможность недоступна.Подключите адаптер или выберите поддержанный режим.
CompleteВыполнение закончено; это состояние жизненного цикла.Отдельно проверьте итог: Complete не означает Passed.

Save and rerun case запускает сохраненный подходящий сценарий с выбранными условиями. После изменения зафиксированных условий может потребоваться новый план. Export report копирует отчет для передачи. Передавайте всю папку с изображениями, а не один HTML-файл.

Обрезанный текст и замечания к разметке

AnalyzeLayout исследует зарегистрированные цели или все зарегистрированные виджеты, если список целей пуст. Он может отмечать обрезание, пересечения и мелкие метрики шрифта. Рядом добавьте CaptureCheckpoint, чтобы видеть настоящий UI.

Desired - требуемый размер текстовой разметки, visible - измеренная доступная область отсечения. Если описанию нужно 84 пикселя высоты, а выделено 46, замечание возможно и на 1920 x 1080. Большой экран не увеличивает маленькое текстовое поле автоматически.

Это кандидаты на проверку, а не OCR-распознавание каждого символа и не доказательство ошибки любого пересечения. Перед правкой проверьте декоративные слои, прокрутку и намеренное сокращение текста.

  1. Откройте точный случай и виджет. Сверьте язык, разрешение и масштаб.
  2. Посмотрите оригинальный снимок и разметку. Проверьте перенос строк, размер контейнера, anchors, padding или подходящую короткую подпись.
  3. Нажмите Compile и Save, повторите ту же конфигурацию и затронутые соседние условия.
  4. Если поведение намеренное, задайте узкое suppression в настройках сценария: RuleId, локатор, применимые условия и понятный Reason. Причина исключения должна оставаться доступной для проверки.

Для нестандартного рисования, rich text и еще не созданных элементов списка может требоваться адаптер проекта. Неподдержанная проверка не считается пройденной.

Одобрение эталона и повторное сравнение

Baseline - изображение, которое вы осознанно приняли за правильное для одной конфигурации. Снимок без сравнения полезен для просмотра, но еще не является проверкой визуальной регрессии.

  1. На шаге снимка включите Compare Baseline. Скомпилируйте и сохраните UI и fixture, сохраните сценарий. Вернитесь в Matrix, нажмите Preview selected cases and exclusions, выберите обновленный случай и запустите Save and run selected case. После изменения условий не используйте повтор старого зафиксированного случая из Runs. Первое сравнение нового сочетания обычно вернет NoBaseline.
  2. В Runs изучите именно этот снимок и нажмите Review baseline source. Другой путь: Baselines > Refresh completed runs, затем выберите завершенный исходный случай и checkpoint menu_state.
  3. При необходимости нажмите Review checkpoint. Откройте Current в полном размере через Open original или Comparison report. Сверьте исходный результат, язык, разрешение и масштаб.
  4. Введите имя проверяющего, проверьте пороги и нажмите Approve reviewed image только для правильного изображения. Если исходные данные изменились после просмотра, сначала изучите новый вариант.
  5. Повторите тот же случай. Теперь он может сравниваться с совместимым одобренным эталоном. При различии просмотрите Current, Baseline и Diff.

Одобрение - отдельное действие. Каждому сочетанию языка, разрешения, масштаба, ввода и совместимого профиля рисования нужен свой эталон. Изменение версии движка, Revision сценария или профиля шрифтов/рисования может потребовать нового просмотра.

Пороги и анимированные области

По умолчанию Channel tolerance равен 8, а Allowed changed fraction - 0.0005, то есть 0.05% немаскированных пикселей. Не увеличивайте пороги ради сокрытия дефекта. В Advanced source and masks можно указать JSON-маску для намеренно меняющейся области:

{"schemaVersion":1,"masks":[{"name":"clock","reason":"Animated clock","x":30,"y":20,"width":160,"height":40}]}

Координаты задаются в пикселях снимка. У каждой маски должны быть имя и причина; закрывать весь снимок нельзя. Храните одобренные эталоны вместе с проверяемыми файлами проекта.

Клавиатура, геймпад и модальные окна

Первый пример проверяет неподвижный экран. Для взаимодействия включите focusable у настоящих кнопок, задайте навигацию и обычную обработку OnClicked. При открытии экрана задайте режим ввода игрока и начальный фокус.

ОперацияНазначение
FocusWidgetЗадать известную начальную точку. Это еще не проверка навигации.
SendKeyПередать Down, Enter или Escape интерфейсу с фокусом.
SendGamepadButtonПередать Gamepad_DPad_Down или Gamepad_FaceButton_Bottom.
ClickWidgetНажать зарегистрированный контрол поддержанным маршрутом ввода.
AssertFocusedПроверить, какой контрол получил фокус.
AssertNoModalИспользовать явный наблюдатель модального состояния fixture.

Для проверки навигации задайте кнопкам явные переходы Down/Up, отправьте клавишу, затем проверьте фокус. Не вызывайте OnClicked прямо из fixture вместо проверки ввода. SendKey и SendGamepadButton используют текущий фокус, а не Target.

Для модальных окон реализуйте SupportsModalObservation = true и HasOpenModal, возвращающий настоящий флаг открытого окна. Обновляйте его в обычном потоке открытия и закрытия. В OnlyInputModes разделяйте шаги Keyboard и Gamepad.

PIE - запуск игры внутри редактора. Для проверки в том же процессе нужны полноценные CaptureInputState/RestoreInputState, реализованные вашей игрой. Если их нет, используйте отдельный процесс. Программный маршрут геймпада не требует физического контроллера; особенности реального оборудования проверяются отдельно.

Запуск из командной строки и отчеты

Сохраненные сценарии можно запускать из PowerShell, например на сборочном сервере. Откройте терминал в папке проекта и замените пути из примера на свои. Если плагин установлен в движок, используйте его папку Scripts вместо пути внутри проекта.

$project = 'D:\Games\MyGame\MyGame.uproject'
$engine = 'D:\Epic\UE_5.8'
.\Plugins\ScreenDoctor\Scripts\Run-ScreenDoctorSuite.ps1   -ProjectFile $project -EngineRoot $engine   -SuiteAsset '/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite'   -Mode EditorStandalone

/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite - путь объекта suite из примера, а не путь к файлу Windows. Если переименовали ассет, укажите его настоящий путь. Скрипты находятся в Scripts плагина ScreenDoctor.

Код выходаЗначение
0Все выбранные обязательные проверки прошли. Могут оставаться заранее объявленные необязательные или подавленные замечания.
1Не выполнено хотя бы одно ожидаемое условие, если нет ошибки с более высоким приоритетом.
2Ошибка настройки, выполнения или хранения, включая пустой выбранный план.
3Неразрешенное обязательное замечание, отсутствие эталона, неподдержанная/пропущенная проверка, отмена или незавершенный запуск.

HTML предназначен для просмотра, JSON содержит полные данные, JUnit используется сборочными системами. История обычно хранится в <Project>/Saved/ScreenDoctor, эталоны - в <Project>/ScreenDoctor/Baselines. Передавайте полную папку отчета, чтобы работали изображения и относительные ссылки.

Cancel owned queue останавливает текущую очередь плагина и сохраняет доступные частичные результаты. Очистка истории включается явно: Clear-ScreenDoctorHistory.ps1 сначала показывает список, удаление требует -Apply. Не удаляйте одобренные эталоны как обычную историю запусков.

Для снимков нужна настоящая GPU-сессия рисования. NullRHI не создает изображение UI. Проверки и отчеты работают локально; внешняя служба анализа не требуется.

Проверка собранной Development-игры

Packaged-игра запускается отдельно от редактора. Для ScreenDoctor используйте конфигурацию Development: в Shipping и Test модуль запуска проверок исключен.

  1. В Edit > Project Settings > Packaging выберите нужные карты и языки.
  2. Если Blueprint fixture, виджет, scenario и suite не включаются другими ссылками, добавьте их папку в Additional Asset Directories to Cook. Для примера это /Game/UITests. Cook подготавливает ассеты для готовой игры; доступность в редакторе не означает автоматическое включение в сборку.
  3. Соберите Win64 Development, используя инструменты сборки для вашей установки Unreal.
  4. В Matrix включите Use packaged Development executable, нажмите Browse... и выберите настоящий Development-файл игры .exe.
  5. Посмотрите план и запустите один случай. Сверьте viewport, язык и файлы результата, затем запускайте весь набор.

Если в готовой игре нет перевода или шрифта, включите соответствующие локализованные данные и шрифты. Руководство рассчитано на UE 5.5-5.8; используйте согласованные версии движка и плагина при выполнении и одобрении эталонов.

Частые вопросы

Можно проверять больше трех разрешений?

Да. Добавляйте и удаляйте размеры в Matrix. Три колонки на иллюстрациях - один выбранный профиль, а не ограничение плагина.

125% меняет масштаб Windows?

Нет. Это масштаб текста, который реализован вашим fixture или настройками игры. DPI физического монитора является другим параметром.

Установка автоматически подключает все экраны игры?

Нет. Подключите экран или семейство экранов через fixture, постоянные ID и шаги сценария. В примере сначала используется небольшой виджет.

Needs review всегда означает настоящий баг?

Нет. Оцените изображение и измерения. Обрезание или декоративное пересечение могут быть предусмотрены вашим дизайном.

Повторный запуск сам одобрит изображение?

Нет. Нужны отдельный просмотр и явная кнопка Approve reviewed image.

Фэнтези-экран и учебные ассеты входят в плагин?

Фэнтези-экран на снимках относится к отдельному проекту-иллюстрации. Небольшой UMG-пример вы создаете по руководству; установка плагина сама эти игровые ассеты не создает.

Нужен аккаунт или облачный сервис анализа?

ScreenDoctor выполняет проверки через Unreal локально и сохраняет отчеты. Внешний аккаунт для анализа не требуется.
