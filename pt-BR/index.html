ScreenDoctor 1.0.0 testa interfaces no Unreal Engine 5.5-5.8, Windows 64-bit e UMG. UMG é o sistema do Unreal para criar menus, botões e outras telas do jogo.

Primeira vez no Unreal? Siga o exemplo pequeno. Uma fixture é um adaptador Blueprint que abre a tela para o teste. Um scenario descreve verificações. Uma suite agrupa cenários e configurações.

O plugin executa os caminhos que você descreve. Ele não explora todos os menus sozinho nem corrige automaticamente a interface. As explicações estão traduzidas; nomes de botões e nós Blueprint permanecem em inglês para serem encontrados no editor.

Instalar e abrir o plugin

Escolha a versão do motor

Use o pacote ScreenDoctor correspondente ao Unreal Engine 5.5, 5.6, 5.7 ou 5.8. A versão aparece abaixo da instalação em Unreal Engine > Library no Epic Games Launcher.

Instalar pelo Fab

  1. Feche o Unreal Editor. Encontre ScreenDoctor na biblioteca Fab do launcher e instale para o motor do seu projeto.
  2. Abra o projeto e Edit > Plugins. Procure ScreenDoctor, ative se necessário e reinicie o editor.
  3. Abra Tools > ScreenDoctor.

Instalar um ZIP no projeto

A pasta do projeto contém o arquivo .uproject. Crie Plugins se necessário, feche o Unreal e extraia nesta estrutura:

MyGame/
  MyGame.uproject
  Content/
  Plugins/
    ScreenDoctor/
      ScreenDoctor.uplugin
      Resources/
      Source/

Depois abra o projeto, ative ScreenDoctor em Edit > Plugins, reinicie e abra Tools > ScreenDoctor. Um pacote compilado também inclui Binaries. Instale uma única cópia, no motor ou no projeto. Pacotes apenas com fontes exigem ferramentas C++ do Visual Studio e Windows SDK compatíveis, mesmo em projetos Blueprint. Para não compilar, escolha o pacote compilado da versão correta.

Se ainda não existe um projeto

Abra o Unreal, escolha Games > Blank > Blueprint, dê um nome e clique em Create. Guarde em uma pasta fácil de localizar. O Content Drawer, na parte inferior ou por Ctrl+Espaço, contém os assets: elementos salvos, como widgets e cenários.

Primeira verificação em um projeto vazio

Comece com uma tela, um idioma e uma resolução. O exemplo não exige C++. Menus e nós são indicados em inglês; use os equivalentes no idioma do seu editor.

  1. No Content Drawer > Content, clique com o botão direito na área de assets, escolha New Folder e crie UITests.
  2. Nessa pasta, escolha User Interface > Widget Blueprint e User Widget como classe pai, se solicitado. Nomeie WBP_UIExample e abra.
  3. No Designer, adicione um Canvas Panel raiz se não houver. Dentro, adicione Text, nomeie TitleLabel na Hierarchy e ative Is Variable em Details. Texto exatamente Settings, fonte 32, posição Canvas X=100, Y=100, tamanho 600 x 100.
  4. Adicione ao Canvas um Button chamado ContinueButton, com Is Variable e Is Focusable ativos. Posição X=100, Y=250, tamanho 300 x 70. Seu filho Text mostra Continue. Título e botão devem ser filhos separados do Canvas, não um do outro.
  5. Clique em Compile e Save.
  6. Conclua Conectar o widget e Descrever o cenário; depois volte aqui.
  7. Em Suites, escolha Create suite e salve DA_UIFirstSuite em Content/UITests. Abra Edit suite properties e defina SuiteId = first_ui_suite. Em janela compacta, use Back to controls. Em Scenarios, selecione DA_UIFirstScenario e Add scenario to suite.
  8. Em Matrix, use Add resolution para adicionar 1280 x 720 e Remove para retirar o 1280 x 800 inicial, se existir. Mantenha 100%, en e Keyboard. Altere idioma e entrada em Edit cultures, input modes, exclusions and case limit e volte aos controles se necessário. Não ative a execução packaged.
  9. Use Preview selected cases and exclusions, selecione o único caso e Save and run selected case. O widget abre em um processo de teste separado; o Play normal do editor não é necessário.
  10. Em Runs, escolha o resultado concluído e a imagem. Analise os cinco passos e menu_state. A primeira captura é salva sem comparação com referência; ainda não comprova correspondência visual.
Compile e salve widget e fixture antes do teste. Run salva suite e cenário, mas não compila nem salva todos os Blueprints do jogo.

Conectar o widget usando uma fixture

A fixture deriva de ScreenDoctorFixture. Ela cria a tela, registra controles e informa quando a interface está pronta. Não coloque a fixture no nível nem adicione a própria fixture ao viewport.

Criar o asset

  1. Abra Tools > ScreenDoctor > Scenarios, escolha Create scenario e salve DA_UIFirstScenario em Content/UITests. Mantenha selecionado.
  2. Clique em Create Blueprint fixture, salve e abra BP_UIFixture. O botão atribui ao cenário, mas cria um Blueprint vazio, não um menu funcional.
  3. Em My Blueprint, crie Menu do tipo WBP_UIExample Object Reference e compile. Em Functions > Overrides, escolha OpenScreen.

OpenScreen: criar e retornar a interface

Adicione nós com o botão direito e conecte os pinos brancos de execução em ordem. Create Widget usa WBP_UIExample e Get Player como Owning Player. Salve Return Value em Menu e no RootWidget herdado. Ative Show Inherited Variables caso ele esteja oculto.

OpenScreen
  Create Widget (Class = WBP_UIExample, Owning Player = GetPlayer)
  -> Set Menu = Return Value
  -> Set RootWidget = Menu
  -> Add to Viewport (Target = Menu)
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = title, Context = ""
       Widget: Menu.TitleLabel
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = continue, Context = ""
       Widget: Menu.ContinueButton
  -> Return Menu

O Target de cada Register Widget recebe Get Registry. No pino Locator, use Make Screen Doctor Locator ou divida a estrutura e preencha os três campos separadamente. A partir de Menu, obtenha a referência real TitleLabel ou ContinueButton para Widget. Retorne Menu no resultado da função: um objeto widget, não um booleano.

IsReady: aguardar a tela

Adicione o override IsReady. Valide Menu com Is Valid e Branch. Se inválido, retorne false; se válido, retorne Is In Viewport de Menu. A implementação padrão retorna false, causando timeout se não for substituída.

CleanupCase: limpar o estado

Adicione CleanupCase. No nó de entrada, escolha Add Call to Parent Function, conecte a chamada e depois limpe Menu para None. O pai remove RootWidget e limpa o registro. Mantenha CaptureInputState e RestoreInputState padrão neste tutorial de processo separado. Compile, Save e siga para o cenário.

Comece com 100%. Outras escalas dependem da implementação real descrita em Matrix.

Descrever ações e verificações

Selecione DA_UIFirstScenario em Scenarios. Defina ScenarioId = first_ui, Revision = 1 e Fixture Class = BP_UIFixture.

  1. Abra Edit fixture / steps, expanda Steps em Details e adicione cinco elementos pelo + do array.
  2. Preencha na ordem da tabela, mantendo Required ativo e timeouts positivos: 5 segundos para os quatro primeiros passos.
  3. Em passos com alvo, separe Target.ScreenId e Target.TestId; deixe Context vazio. Em AnalyzeLayout, adicione um item em Layout > Targets.

Selecionar um passo abre seu editor. Cada StepId precisa ser único. Após renomear, excluir ou duplicar, selecione novamente o passo correto. Preserve IDs para a mesma finalidade e aumente Revision ao mudar intencionalmente o contrato do teste.

Na janela compacta, saia de Details com Back to controls. Volte à primeira verificação para criar a suite e executar um caso.

Encontrar widgets por IDs estáveis

Um locator possui três campos separados:

CampoExemploFinalidade
ScreenIddemo_menuTela que contém o controle.
TestIdtitleControle dentro da tela.
Contextvazio ou item:42Chave opcional para um item repetido.

Registre esses valores com o objeto widget real ao abrir a tela. Não coloque demo_menu/title inteiro em TestId. Textos traduzidos, coordenadas e índices de filhos não são IDs estáveis.

No tutorial, digite os IDs diretamente. Refresh IDs e Assign locator to selected StepId leem o registro de uma fixture ScreenDoctor ativa em PIE. Play normal não cria essa fixture nem procura todos os widgets do jogo.

Dois widgets vivos com o mesmo locator causam ambiguidade; use IDs ou Context diferentes. Em listas virtualizadas, o adaptador deve rolar até o item e criar a entrada antes de registrá-la. Uma entrada ainda não criada não comprova defeito na interface.

Escolher resoluções, idiomas e tamanho do texto

Selecione a suite e abra Matrix. Adicione seus próprios tamanhos, inclusive 4K, ultrawide e retrato. Três resoluções não são um limite.

  1. Em Viewport resolutions, informe Width e Height inteiros de 1 a 16384 e clique em Add resolution. Remove exclui a linha. Mantenha ao menos um tamanho válido.
  2. Em Text scales, informe um percentual como 125 e Add text scale. Remova valores pelas linhas. O campo percentual recebe 125; TextScales armazena 1.25.
  3. Em Edit cultures, input modes, exclusions and case limit, adicione en, de, fr e os modos de entrada suportados. O jogo precisa ter traduções e fontes; escolher uma cultura não traduz textos.
  4. Atualize a prévia: cada cenário combina resoluções, culturas, escalas e entradas, depois aplica exclusões. Um cenário e uma entrada, duas resoluções, três culturas e duas escalas resultam em 12 casos.
  5. Execute um caso e depois Save and run suite. Mais de 20 casos selecionados exigem confirmar a estimativa. Case Limit limita o plano; Exclusions remove combinações intencionalmente.

Aplicar a escala à interface real

Implemente ApplyTextScale na fixture; o padrão aceita apenas 1.0. Crie o float RequestedScale em BP_UIFixture com valor inicial 1.0. No override, para Scale > 0 e Scale <= 3, salve Scale e retorne true; caso contrário, false. Esse é o intervalo do adaptador de exemplo. O callback ocorre antes de OpenScreen, quando Menu ainda não existe.

Em OpenScreen, após Set Menu e antes de Add to Viewport, obtenha Menu.TitleLabel e Get Font. Conecte a saída a Break Slate Font Info e adicione Make Slate Font Info. Ligue os campos existentes correspondentes de Break a Make: Font Family (Font Object), Typeface (Typeface Font Name), material, contorno e demais configurações disponíveis. Apenas em Size use Round(32 * RequestedScale) no lugar do tamanho anterior. Conecte o resultado de Make a Set Font em Menu.TitleLabel e ligue os pinos brancos de execução. Se necessário, arraste do pino da fonte e procure Slate Font Info. O exemplo escala o título; repita a política nos outros textos ou use a configuração real do jogo. Calcule sempre a partir do tamanho base salvo, não de um tamanho já ampliado.

Viewport é a área de desenho; escala do texto é um ajuste do jogo. Escala do Windows e DPI físico do monitor são conceitos separados. Matrix em 125% não muda o DPI do Windows.

Ler os resultados em Runs

  1. Em Runs, escolha uma execução concluída no seletor superior.
  2. Escolha cenário à esquerda, checkpoint e entrada. Colunas mostram resolução/escala e linhas mostram culturas.
  3. Filtre com All cases, Needs review, Passed ou More filters. Contadores sem filtro podem incluir exclusões planejadas; elas não são casos executados.
  4. Selecione uma célula, clique em Inspect case e use Next finding para ver locator, Expected e Actual.
  5. 100% mostra pixels reais; role a imagem e volte com Fit. Open original abre o arquivo. Geometry snapshot é uma medição separada, não uma sobreposição garantida em cada pixel da captura.
StatusSignificadoO que fazer

Needs review / ReviewNeededUma condição medida precisa de inspeção.Examine o widget e a imagem.
NoBaselineNão existe referência compatível aprovada.Revise e aprove uma imagem correta.

Save and rerun case usa o cenário salvo correspondente. Uma mudança no contrato congelado pode exigir um novo plano. Export report copia o pacote para compartilhar; envie toda a pasta com imagens, não apenas o HTML.

Entender cortes e problemas de layout

AnalyzeLayout examina os alvos registrados ou todos os widgets registrados quando Targets está vazio. Pode apontar cortes, sobreposições e métricas de fonte pequenas. Adicione um CaptureCheckpoint próximo da análise.

Desired é o tamanho solicitado pelo layout do texto; visible é a região de recorte medida. Uma descrição que precisa de 84 pixels de altura e recebe 46 pode gerar observação mesmo em 1920 x 1080. Uma tela grande não aumenta um campo pequeno automaticamente.

São candidatos para revisão, não OCR de cada caractere nem prova de que toda sobreposição está errada. Verifique camadas decorativas, rolagem e truncamentos intencionais.

  1. Abra o caso e alvo exatos; confirme idioma, resolução e escala.
  2. Examine original e layout: quebra de linha, contêiner, âncoras, espaçamento ou legenda menor.
  3. Compile, salve e repita as mesmas condições e as demais afetadas.
  4. Se for intencional, adicione uma supressão específica no cenário com RuleId, locator, dimensões e Reason útil. Preserve a justificativa junto ao resultado.

Desenho personalizado, rich text e entradas ainda não criadas podem precisar de adaptadores. Unsupported não equivale a aprovação.

Aprovar uma referência e comparar novamente

Uma baseline é uma imagem aprovada conscientemente como correta para uma configuração. Capturar sem comparar ainda não verifica regressão visual.

  1. Ative Compare Baseline na captura. Compile e salve widget e fixture, depois salve o cenário. Em Matrix, use Preview selected cases and exclusions, selecione o caso atualizado e Save and run selected case. Não repita o antigo caso congelado em Runs após mudar o contrato. A primeira comparação normalmente resulta em NoBaseline.
  2. Examine essa captura em Runs e escolha Review baseline source. Ou abra Baselines, Refresh completed runs e selecione o caso original concluído e menu_state.
  3. Use Review checkpoint se necessário. Analise Current em Open original ou Comparison report e confira identidade, cultura, resolução e escala.
  4. Digite o nome do revisor, confira os limites e clique em Approve reviewed image apenas se estiver correta. Se a origem mudou, revise-a novamente.
  5. Execute o mesmo caso. Se houver diferença, examine Current, Baseline e Diff.

Executar não aprova. Cada cultura, resolução, escala, entrada e perfil de renderização compatível precisa da referência correspondente. Uma alteração de motor, Revision ou perfil de fontes/renderização pode exigir nova revisão.

Limites e regiões animadas

Channel tolerance padrão é 8; Allowed changed fraction é 0.0005, ou 0.05% dos pixels sem máscara. Não aumente para esconder defeitos. Advanced source and masks permite um JSON para uma região que muda intencionalmente:

{"schemaVersion":1,"masks":[{"name":"clock","reason":"Animated clock","x":30,"y":20,"width":160,"height":40}]}

Coordenadas usam pixels da captura. Cada máscara precisa de nome e motivo; não é permitido cobrir a imagem inteira. Guarde referências com os assets revisados do projeto.

Teclado, gamepad e janelas modais

O primeiro exemplo é estático. Para interagir, torne botões reais focalizáveis, defina navegação e eventos OnClicked normais. Configure modo de entrada e foco inicial ao abrir.

OperaçãoUso
FocusWidgetDefinir o foco inicial, sem comprovar navegação.
SendKeyEnviar Down, Enter ou Escape ao foco da interface controlada.
SendGamepadButtonEnviar Gamepad_DPad_Down ou Gamepad_FaceButton_Bottom.
ClickWidgetClicar no controle registrado pela rota de entrada suportada.
AssertFocusedVerificar qual controle está com foco.
AssertNoModalConsultar o observador modal explícito da fixture.

Defina Down/Up explícitos, envie a tecla e confira o foco. Não substitua isso por uma chamada direta a OnClicked. SendKey e SendGamepadButton usam o foco atual, não Target.

Implemente SupportsModalObservation = true e HasOpenModal com o booleano real atualizado pelo fluxo normal de abrir/fechar. OnlyInputModes separa passos Keyboard e Gamepad.

PIE significa Play In Editor. No mesmo processo, são necessários CaptureInputState/RestoreInputState completos e controlados pelo jogo. Sem eles use outro processo. O roteamento de gamepad por software não exige controle físico; o comportamento do hardware é uma verificação diferente.

Automatizar e guardar relatórios

Execute as suites salvas diretamente com o commandlet ScreenDoctor integrado ao Unreal, por exemplo em uma tarefa de build. Abra um terminal PowerShell e substitua os caminhos do projeto e do editor. Use a mesma versão do motor que o projeto. Não são necessários arquivos de script adicionais.

$project = 'D:\Games\MyGame\MyGame.uproject'
$editor = 'D:\Epic\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe'
& $editor $project -run=ScreenDoctor -Action=Run -Suite='/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite' -Mode=EditorStandalone -NullRHI -unattended

/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite é o caminho de objeto do asset da suite, não um arquivo Windows. Ajuste se renomeou o asset. Salve a suite, o cenário, o widget e a fixture antes de executar.

Código de saídaSignificado
0Todas as verificações obrigatórias passaram; observações opcionais ou suprimidas declaradas podem permanecer.
1Alguma asserção falhou, sem erro de prioridade maior.
2Erro de configuração, execução ou armazenamento, inclusive plano vazio.
3Revisão obrigatória pendente, referência ausente, capacidade indisponível/passo ignorado, cancelamento ou execução incompleta.

HTML serve para leitura, JSON preserva detalhes e JUnit integra ferramentas de build. O histórico costuma ficar em <Project>/Saved/ScreenDoctor, e as referências em <Project>/ScreenDoctor/Baselines. Mantenha o pacote completo.

Cancel owned queue interrompe a fila do plugin e mantém os resultados disponíveis. Para limpar o histórico, execute a ação History abaixo com sua pasta de relatórios. Ela apenas mostra as pastas elegíveis. Adicione -Apply após conferir a prévia. -KeepLast=20 mantém as 20 execuções e as 20 filas concluídas mais recentes. Referências aprovadas e execuções incompletas são protegidas. Mantenha as referências separadas do histórico comum.

& $editor $project -run=ScreenDoctor -Action=History -OutputRoot='D:\Games\MyGame\Saved\ScreenDoctor' -KeepLast=20 -NullRHI -unattended

Nestes exemplos, -NullRHI se aplica ao commandlet coordenador. Run inicia processos separados com renderização GPU para as capturas; eles precisam de uma sessão gráfica funcional. Capturar o jogo com NullRHI não produz uma imagem de UI. Verificações e relatórios ficam locais, sem serviço de análise online obrigatório.

Testar um jogo empacotado em Development

Um jogo packaged roda fora do editor. Use Development para ter o executor de testes; Shipping e Test excluem esse módulo.

  1. Em Edit > Project Settings > Packaging, selecione mapas e culturas necessários.
  2. Inclua a pasta de fixture, widget, cenário e suite em Additional Asset Directories to Cook quando não houver outra referência. Aqui é /Game/UITests. Cook prepara assets para o jogo; existir no editor não garante inclusão no pacote.
  3. Gere Win64 Development com as ferramentas exigidas pela instalação Unreal.
  4. Em Matrix, ative Use packaged Development executable, clique em Browse... e escolha o .exe Development real.
  5. Confira o plano, rode um caso e valide viewport, cultura e arquivos antes da suite completa.

Inclua traduções e fontes. O guia cobre UE 5.5-5.8; use versões correspondentes de plugin e motor na execução e aprovação das referências.

Perguntas frequentes

Posso usar mais de três resoluções?

Sim. Adicione e remova tamanhos em Matrix. Três colunas de exemplo não são um limite.

125% altera a escala do Windows?

Não. Solicita a escala de texto implementada pelo jogo ou pela fixture. DPI do monitor é separado.

A instalação conecta todos os menus?

Não. Conecte telas ou famílias de telas com fixture, IDs estáveis e passos. Comece com o widget pequeno.

Needs review confirma um bug?

Não. Examine imagem e medidas; cortes e sobreposições podem ser intencionais.

Executar novamente aprova a imagem?

Não. É preciso revisão separada e Approve reviewed image.

O plugin inclui a UI de fantasia e os assets do tutorial?

A fantasia pertence a um projeto ilustrativo separado. Você cria o pequeno exemplo UMG seguindo este guia; a instalação não gera esses assets de jogo.

Preciso de uma conta de análise na nuvem?

Não. ScreenDoctor executa os testes pelo Unreal e grava relatórios locais.
