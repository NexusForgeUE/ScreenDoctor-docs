ScreenDoctor 1.0.0 comprueba interfaces en Unreal Engine 5.5-5.8, Windows 64-bit y UMG. UMG es el sistema de Unreal para crear menús, botones y otras pantallas del juego.

¿Es tu primera vez en Unreal? Sigue el ejemplo pequeño. Una fixture es un adaptador Blueprint que abre la pantalla para la prueba. Un scenario describe las comprobaciones. Una suite agrupa escenarios y configuraciones.

El plugin ejecuta los recorridos que describes. No explora por sí solo todos los menús ni repara automáticamente la interfaz. Las explicaciones están traducidas; los nombres ingleses de botones y nodos Blueprint se mantienen para encontrarlos en el editor.

Instalar y abrir el plugin

Elige la versión del motor

Usa el paquete ScreenDoctor para tu Unreal Engine: 5.5, 5.6, 5.7 o 5.8. La versión aparece bajo la instalación en Unreal Engine > Library de Epic Games Launcher.

Instalación desde Fab

  1. Cierra Unreal Editor. Busca ScreenDoctor en tu biblioteca de Fab del lanzador e instálalo para el motor de tu proyecto.
  2. Abre el proyecto y Edit > Plugins. Busca ScreenDoctor, actívalo si hace falta y reinicia el editor.
  3. Abre Tools > ScreenDoctor.

Instalación de un ZIP en el proyecto

La carpeta del proyecto contiene el archivo .uproject. Crea Plugins si no existe, cierra Unreal y extrae con esta estructura exacta:

MyGame/
  MyGame.uproject
  Content/
  Plugins/
    ScreenDoctor/
      ScreenDoctor.uplugin
      Resources/
      Source/

Después abre el proyecto, activa ScreenDoctor en Edit > Plugins, reinicia y abre Tools > ScreenDoctor. Un paquete compilado también incluye Binaries. Instala una sola copia, en el motor o en el proyecto. Un paquete de código fuente necesita herramientas C++ de Visual Studio y Windows SDK compatibles, incluso para un proyecto Blueprint. Para evitar compilar, usa el paquete compilado correspondiente.

Si todavía no tienes proyecto

Inicia Unreal, elige Games > Blank > Blueprint, introduce un nombre y pulsa Create. Guarda el proyecto en una carpeta reconocible. Content Drawer, abajo o mediante Ctrl+Espacio, contiene los assets: elementos guardados, como widgets o escenarios.

Primera comprobación desde un proyecto vacío

Empieza con una pantalla, un idioma y una resolución. No necesitas C++ para este ejemplo. Los nombres de menús y nodos se muestran en inglés; busca sus equivalentes si usas otro idioma en el editor.

  1. En Content Drawer > Content, haz clic derecho en la zona de assets, selecciona New Folder y crea UITests.
  2. Dentro, elige User Interface > Widget Blueprint y el padre User Widget si se solicita. Nombra el asset WBP_UIExample y ábrelo.
  3. En Designer, añade un Canvas Panel raíz si no existe. Añade un control Text dentro, nómbralo TitleLabel en Hierarchy y activa Is Variable en Details. Texto exactamente Settings, fuente 32, posición Canvas X=100, Y=100, tamaño 600 x 100.
  4. Añade un Button al Canvas llamado ContinueButton. Activa Is Variable e Is Focusable. Posición X=100, Y=250, tamaño 300 x 70. Su Text hijo muestra Continue. El título y el botón son hijos separados del Canvas, no uno del otro.
  5. Pulsa Compile y Save.
  6. Completa Conectar el widget y Describir el escenario; después vuelve aquí.
  7. En Suites, pulsa Create suite y guarda DA_UIFirstSuite en Content/UITests. Abre Edit suite properties, establece SuiteId = first_ui_suite y, en una ventana compacta, vuelve con Back to controls. En Scenarios selecciona DA_UIFirstScenario y pulsa Add scenario to suite.
  8. En Matrix, añade 1280 x 720 con Add resolution y elimina el valor inicial 1280 x 800 con Remove, si aparece. Conserva 100%, en y Keyboard. Edita idioma y entrada mediante Edit cultures, input modes, exclusions and case limit; vuelve a los controles si hace falta. Deja desactivada la ejecución packaged.
  9. Pulsa Preview selected cases and exclusions, elige el único caso y Save and run selected case. Se abre un proceso de prueba separado; no hace falta pulsar el Play normal del editor.
  10. En Runs elige el resultado completado y su imagen. Revisa los cinco pasos y menu_state. Esta primera captura no compara con una referencia y todavía no demuestra coincidencia visual.
Compila y guarda el widget y la fixture antes de ejecutar. Run guarda la suite y el escenario, pero no compila ni guarda todos los Blueprints del juego.

Conectar el widget mediante una fixture

La fixture deriva de ScreenDoctorFixture. Crea la pantalla, registra controles y comunica cuándo está lista. No coloques la fixture en el nivel ni la añadas como si fuera un widget al viewport.

Crear el asset

  1. Abre Tools > ScreenDoctor > Scenarios. Pulsa Create scenario, guarda DA_UIFirstScenario en Content/UITests y mantenlo seleccionado.
  2. Pulsa Create Blueprint fixture, guarda y abre BP_UIFixture. El botón lo asigna al escenario, pero crea un Blueprint vacío, no un menú terminado.
  3. En My Blueprint crea la variable Menu de tipo WBP_UIExample Object Reference y compila. En Functions > Overrides selecciona OpenScreen.

OpenScreen: crear y devolver la interfaz

Añade nodos con clic derecho y conecta los pines blancos de ejecución en orden. Create Widget usa WBP_UIExample y Get Player como Owning Player. Guarda Return Value en Menu y en el RootWidget heredado; activa Show Inherited Variables si está oculto.

OpenScreen
  Create Widget (Class = WBP_UIExample, Owning Player = GetPlayer)
  -> Set Menu = Return Value
  -> Set RootWidget = Menu
  -> Add to Viewport (Target = Menu)
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = title, Context = ""
       Widget: Menu.TitleLabel
  -> GetRegistry -> Register Widget
       Locator: ScreenId = demo_menu, TestId = continue, Context = ""
       Widget: Menu.ContinueButton
  -> Return Menu

Conecta Target de cada Register Widget a Get Registry. En Locator utiliza Make Screen Doctor Locator o divide el pin de estructura y rellena tres campos separados. Desde Menu obtén la referencia real TitleLabel o ContinueButton para Widget. Devuelve Menu en la salida: la función espera un objeto widget, no un booleano.

IsReady: esperar a que esté lista

Añade el override IsReady. Comprueba Menu con Is Valid y Branch. Devuelve false si no es válido y, si lo es, devuelve Is In Viewport de Menu. La implementación vacía devuelve false y termina por agotar el tiempo.

CleanupCase: limpiar el estado

Añade CleanupCase. En su entrada, elige con clic derecho Add Call to Parent Function, conecta la llamada y después deja Menu en None. El padre elimina RootWidget y vacía el registro. Mantén CaptureInputState y RestoreInputState por defecto para este ejemplo con proceso separado. Compile, Save y continúa con el escenario.

Primero usa 100%. Añade otras escalas después de implementar el cambio real explicado en Matrix.

Describir acciones y comprobaciones

Selecciona DA_UIFirstScenario en Scenarios. Establece ScenarioId = first_ui, Revision = 1 y Fixture Class = BP_UIFixture.

  1. Abre Edit fixture / steps, despliega Steps en Details y añade cinco elementos con el + del array.
  2. Rellena la tabla en orden. Conserva Required activado y tiempos positivos: 5 segundos para los primeros cuatro pasos.
  3. En pasos con objetivo, introduce Target.ScreenId y Target.TestId por separado; Context vacío. En AnalyzeLayout añade un elemento a Layout > Targets.

Seleccionar un paso abre su editor. Cada StepId es único; vuelve a seleccionar el paso tras renombrarlo, borrarlo o duplicarlo. Conserva los IDs para el mismo propósito y aumenta Revision si cambias deliberadamente el contrato del test.

En ventana compacta, vuelve desde Details con Back to controls. Regresa a la primera comprobación para crear la suite y ejecutar un caso.

Encontrar widgets con identificadores estables

Un locator contiene tres campos separados:

CampoEjemploSignificado
ScreenIddemo_menuPantalla propietaria del control.
TestIdtitleControl dentro de esa pantalla.
Contextvacío o item:42Identidad opcional de un elemento repetido.

Registra esos valores con la referencia real del widget al abrirlo. No pongas demo_menu/title entero en TestId. Los textos traducidos, coordenadas e índices de hijos no son IDs estables.

En el tutorial, escribe los IDs directamente. Refresh IDs y Assign locator to selected StepId leen el registro de una fixture ScreenDoctor activa en PIE. Play normal no crea esa fixture ni escanea todos los widgets.

Dos widgets vivos con el mismo locator son ambiguos: usa IDs o Context distintos. En una lista virtualizada, el adaptador debe desplazarse y crear la entrada antes de registrarla. Que todavía no exista una entrada no demuestra un defecto de UI.

Elegir resoluciones, idiomas y escalas

Selecciona tu suite y abre Matrix. Puedes añadir tamaños propios, incluidos 4K, ultrapanorámicos y verticales; no hay límite de tres resoluciones.

  1. En Viewport resolutions introduce Width y Height enteros de 1 a 16384 y pulsa Add resolution. Remove elimina una fila. Mantén al menos un tamaño válido.
  2. En Text scales introduce un porcentaje como 125 y pulsa Add text scale. Elimina valores junto a sus filas. El campo porcentual recibe 125 y TextScales guarda 1.25.
  3. En Edit cultures, input modes, exclusions and case limit añade en, de, fr y los modos admitidos. El juego debe disponer ya de traducciones y fuentes. Elegir una cultura no traduce textos.
  4. Actualiza el plan. Cada escenario combina todas las resoluciones, culturas, escalas y entradas, y después aplica las exclusiones. Un escenario y una entrada con dos resoluciones, tres culturas y dos escalas generan 12 casos.
  5. Ejecuta uno y luego Save and run suite. Más de 20 casos seleccionados requieren confirmar la estimación. Case Limit limita el plan; Exclusions omite combinaciones intencionalmente.

Aplicar la escala a la UI real

Implementa ApplyTextScale en la fixture; por defecto solo admite 1.0. Crea el float RequestedScale en BP_UIFixture, inicializado a 1.0. En el override, si Scale > 0 y Scale <= 3, guárdalo y devuelve true; en otro caso false. Ese es el rango de este adaptador de ejemplo. El callback ocurre antes de OpenScreen, cuando Menu aún no existe.

En OpenScreen, después de Set Menu y antes de Add to Viewport, obtén Menu.TitleLabel y Get Font. Conecta el resultado a Break Slate Font Info y añade Make Slate Font Info. Conecta los campos existentes correspondientes de Break a Make: Font Family (Font Object), Typeface (Typeface Font Name), material, contorno y los demás ajustes disponibles. Solo para Size usa Round(32 * RequestedScale) en lugar del tamaño anterior. Conecta el resultado de Make a Set Font de Menu.TitleLabel, incluidos los pines blancos de ejecución. Si necesitas encontrar los nodos, arrastra desde el pin de fuente y busca Slate Font Info. El ejemplo escala el título; repite la política en los demás textos o llama al ajuste real del juego. Calcula siempre desde el tamaño base guardado, no desde uno ya ampliado.

Viewport es la superficie de dibujo; escala de texto es un ajuste del juego. El escalado Windows y los DPI físicos del monitor son distintos. Matrix al 125% no cambia los DPI de Windows.

Leer resultados en Runs

  1. En Runs elige una ejecución terminada en el selector superior.
  2. Selecciona escenario a la izquierda, checkpoint y entrada. Las columnas son configuraciones resolución/escala; las filas son culturas.
  3. Filtra con All cases, Needs review, Passed o More filters. Los totales sin filtrar pueden contar exclusiones del plan; no son casos ejecutados.
  4. Selecciona una celda, pulsa Inspect case y usa Next finding para revisar locator, Expected y Actual.
  5. 100% muestra los píxeles reales; desplázate en la imagen y vuelve con Fit. Open original abre el archivo. Geometry snapshot es una medición separada, no una superposición garantizada de la captura.
EstadoSignificadoAcción
PassedPasaron las comprobaciones obligatorias.Revisa también observaciones opcionales.
Needs review / ReviewNeededUna condición medida necesita inspección.Examina ese widget y la imagen.
NoBaselineNo hay referencia compatible aprobada.Revisa y aprueba una imagen correcta.
FailedNo se cumplió una condición del escenario.Lee el paso, Expected y Actual.
Error / ErroredProblema de configuración, ejecución o almacenamiento.Lee el motivo y el registro.
UnsupportedFalta una capacidad requerida.Implementa el adaptador o usa una configuración admitida.
CompleteTerminó la ejecución.Consulta el resultado aparte; no significa Passed.

Save and rerun case usa el escenario guardado correspondiente. Un contrato congelado modificado puede exigir un plan nuevo. Export report copia una carpeta compartible; envía también las imágenes, no solo el HTML.

Entender recortes y problemas de diseño

AnalyzeLayout revisa los objetivos registrados o todos los widgets registrados si Targets está vacío. Puede señalar recortes, superposiciones y métricas de fuente pequeñas. Añade un CaptureCheckpoint cerca del análisis.

Desired es el tamaño solicitado por el texto; visible es su región de recorte medida. Una descripción que necesita 84 píxeles de altura y dispone de 46 puede generar una observación incluso a 1920 x 1080. Una pantalla grande no agranda por sí sola el contenedor.

Son candidatos para revisión, no OCR de cada carácter ni prueba de que toda superposición sea incorrecta. Comprueba capas decorativas, desplazamiento y truncados intencionales.

  1. Abre el caso y objetivo exactos; comprueba idioma, resolución y escala.
  2. Revisa original y diseño: ajuste de línea, tamaño del contenedor, anclajes, márgenes o texto más corto.
  3. Compila, guarda y repite la configuración y otras afectadas.
  4. Si es intencional, crea una supresión específica en el escenario con RuleId, locator, dimensiones y Reason útil. Conserva la justificación junto al hallazgo.

El dibujo personalizado, rich text y entradas todavía no creadas pueden requerir adaptadores explícitos. Unsupported no es una prueba superada.

Aprobar una referencia y volver a comparar

Una baseline es una imagen que apruebas como referencia correcta de una configuración. Capturar sin comparar no comprueba regresiones visuales.

  1. Activa Compare Baseline en la captura. Compila y guarda widget y fixture; guarda el escenario. Ve a Matrix, Preview selected cases and exclusions, selecciona el caso actualizado y Save and run selected case. No repitas el caso congelado anterior desde Runs tras cambiar el contrato. La primera comparación suele dar NoBaseline.
  2. Examina esa captura en Runs y elige Review baseline source. Alternativamente, en Baselines pulsa Refresh completed runs, elige el caso original completado y menu_state.
  3. Usa Review checkpoint si es necesario. Revisa Current a tamaño completo mediante Open original o Comparison report; comprueba identidad, cultura, resolución y escala.
  4. Introduce el nombre del revisor, comprueba umbrales y pulsa Approve reviewed image solo si es correcta. Si la fuente cambió, revísala de nuevo.
  5. Ejecuta el mismo caso otra vez. Ante diferencias, revisa Current, Baseline y Diff.

Ejecutar y aprobar son acciones distintas. Cada idioma, resolución, escala, entrada y perfil de renderizado compatible necesita su referencia. Cambiar motor, Revision o perfil de fuentes/renderizado puede exigir nueva revisión.

Umbrales y regiones animadas

Channel tolerance vale 8 por defecto. Allowed changed fraction vale 0.0005, el 0.05% de los píxeles no enmascarados. No aumentes el umbral para ocultar un fallo. Advanced source and masks admite un JSON para regiones que cambian a propósito:

{"schemaVersion":1,"masks":[{"name":"clock","reason":"Animated clock","x":30,"y":20,"width":160,"height":40}]}

Las coordenadas son píxeles de la captura. Da nombre y motivo a cada máscara; no puedes cubrir toda la imagen. Conserva las referencias junto a los assets revisados.

Teclado, mando y ventanas modales

El tutorial inicial es estático. Para interacción, haz los botones enfocables, define su navegación y sus eventos OnClicked normales. Establece modo de entrada y foco inicial al abrir.

OperaciónUso
FocusWidgetFijar el inicio; por sí solo no prueba navegación.
SendKeyEnviar Down, Enter o Escape a la interfaz con foco controlado.
SendGamepadButtonEnviar Gamepad_DPad_Down o Gamepad_FaceButton_Bottom.
ClickWidgetPulsar el control registrado por la ruta de entrada admitida.
AssertFocusedComprobar el control con foco.
AssertNoModalConsultar el observador modal de la fixture.

Configura Down/Up explícitos, envía la tecla y comprueba el foco. No sustituyas la navegación llamando directamente OnClicked. SendKey y SendGamepadButton usan el foco actual, no Target.

Implementa SupportsModalObservation = true y HasOpenModal con el booleano real que actualizan la apertura y cierre normales. OnlyInputModes separa pasos Keyboard y Gamepad.

PIE significa Play In Editor. Las pruebas dentro del mismo proceso necesitan CaptureInputState/RestoreInputState completos y propios del juego. Sin ellos usa otro proceso. La ruta de mando por software no exige controlador físico; el comportamiento específico del dispositivo es una comprobación diferente.

Automatización e informes

PowerShell ejecuta los assets guardados, también en trabajos de compilación. Abre un terminal en la carpeta del proyecto y cambia las rutas del ejemplo. Si instalaste en el motor, usa su carpeta Scripts del plugin.

$project = 'D:\Games\MyGame\MyGame.uproject'
$engine = 'D:\Epic\UE_5.8'
.\Plugins\ScreenDoctor\Scripts\Run-ScreenDoctorSuite.ps1   -ProjectFile $project -EngineRoot $engine   -SuiteAsset '/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite'   -Mode EditorStandalone

/Game/UITests/DA_UIFirstSuite.DA_UIFirstSuite es la ruta de objeto de la suite, no una ruta de archivo Windows. Modifícala si cambiaste el nombre. Los scripts están en Scripts del plugin.

Código de salidaSignificado
0Pasaron todas las comprobaciones obligatorias; pueden quedar observaciones opcionales o suprimidas declaradas.
1Falló alguna aserción, sin error de mayor prioridad.
2Error de configuración, ejecución o almacenamiento, incluido un plan vacío.
3Revisión obligatoria pendiente, referencia ausente, capacidad no admitida/paso omitido, cancelación o ejecución incompleta.

HTML sirve para leer, JSON guarda el detalle y JUnit se integra con herramientas de compilación. El historial suele estar en <Project>/Saved/ScreenDoctor; las referencias, en <Project>/ScreenDoctor/Baselines. Conserva todo el paquete del informe.

Cancel owned queue detiene la cola del plugin y conserva lo disponible. Clear-ScreenDoctorHistory.ps1 primero muestra lo que se puede limpiar y solo borra con -Apply. No elimines las referencias aprobadas como historial ordinario.

Las capturas requieren una sesión gráfica GPU real; NullRHI no crea imágenes UI. Los datos y los informes se procesan localmente, sin servicio de análisis en línea obligatorio.

Probar un juego empaquetado en Development

Un juego packaged funciona fuera del editor. Usa Development para disponer del módulo de pruebas; Shipping y Test lo excluyen.

  1. En Edit > Project Settings > Packaging, elige mapas y culturas necesarios.
  2. Incluye la carpeta con fixture, widget, scenario y suite en Additional Asset Directories to Cook si no se referencia de otra forma. En este ejemplo es /Game/UITests. Cook prepara los assets para el juego; que existan en el editor no garantiza su inclusión.
  3. Compila Win64 Development con las herramientas que necesita tu instalación Unreal.
  4. En Matrix activa Use packaged Development executable, pulsa Browse... y elige el .exe Development real.
  5. Revisa el plan, ejecuta un caso y verifica viewport, cultura y archivos antes de toda la suite.

Incluye las traducciones y fuentes del idioma. La guía cubre UE 5.5-5.8: mantén versiones compatibles de motor y plugin durante ejecución y revisión de referencias.

Preguntas frecuentes

¿Puedo usar más de tres resoluciones?

Sí. Añade y elimina tamaños en Matrix. Tres columnas de ejemplo no son un límite.

¿125% cambia el escalado de Windows?

No. Solicita la escala de texto implementada por el juego o la fixture. Los DPI del monitor son independientes.

¿La instalación conecta todos los menús?

No. Conecta pantallas o familias de pantallas con una fixture, IDs estables y pasos. El tutorial empieza con un widget pequeño.

¿Needs review confirma un fallo?

No. Examina imagen y medidas: una truncación o superposición puede ser intencional.

¿Repetir la prueba aprueba la imagen?

No. Hace falta revisión separada y Approve reviewed image.

¿Se incluyen la pantalla de fantasía y los assets del tutorial?

La pantalla de fantasía pertenece a un proyecto ilustrativo aparte. Creas el ejemplo UMG siguiendo esta guía; instalar el plugin no genera esos assets del juego.

¿Necesito una cuenta de análisis en la nube?

No. ScreenDoctor ejecuta las pruebas en Unreal y escribe informes locales.
